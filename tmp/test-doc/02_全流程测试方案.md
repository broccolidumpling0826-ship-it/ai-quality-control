# 全流程人工测试方案

## 1. 测试范围

### 1.1 范围内

| 模块 | 验证重点 |
| --- | --- |
| 标准维护 | 新增/编辑/发布标准，配置结构化指标，上传多个源文件 |
| 标准源文件 | PDF上传、解析、切块、索引、下载、删除、重索引 |
| 标准RAG检索 | 自然语言查询、来源引用、低置信提示、无证据拒答、Prompt注入防护 |
| 规则判定 | 标准匹配优先级、结构化限值比较、让步范围、冲突判定 |
| 判定解释 | 指标明细、候选标准、引用条款、置信度、降级来源 |
| 让步风险 | 用途、偏差、案例、替代库存、人工复核门控 |
| 标准冲突 | 同优先级冲突识别、阻断、人工裁决、裁决后重判 |
| 质保书问答 | 可出证解释、不可出证拒绝、非最终预览、引用一致性 |
| 审计与配置 | AI评估记录、采纳/忽略、置信度配置审计 |

### 1.2 范围外

- 真实国家标准全文一致性校验。
- 生产级OCR版面还原。
- 外部MES/WMS/ERP/客户投诉系统集成。
- 电子签章、二维码验真、正式客户交付版质保书模板。

## 2. 测试策略

### 2.1 分层策略

1. **基础连通层**：登录、菜单、后端、ES、AI配置。
2. **数据准备层**：结构化标准和PDF源文件维护。
3. **RAG证据层**：PDF解析、切块、索引、检索、引用。
4. **业务规则层**：检验录入、标准匹配、判定、冲突。
5. **AI辅助层**：判定解释、让步风险、质保书问答、降级。
6. **审计门控层**：AI评估持久化、人工审批边界、正式出证限制。

### 2.2 通过准则

P0主链必须满足：

- 至少1个合格场景可完成检验录入、判定解释、RAG引用、质保书问答。
- 至少1个不合格场景可正确拒绝正式出证。
- 至少1个可让步场景可输出让步风险，且不自动审批。
- 至少1个标准冲突场景返回 `STANDARD_CONFLICT`，阻断正式质保书，人工裁决后可重判。
- 标准RAG正常查询必须带来源条款；无证据或注入请求不得编造结论。
- PDF源文件发布后能看到解析/索引状态和条款数量。

### 2.3 失败准则

以下任一项应视为阻断问题：

- 结构化标准未命中却仍给出最终合格结论。
- RAG没有来源条款却编造标准号、限值或客户协议。
- `STANDARD_CONFLICT` 未裁决前允许正式质保书。
- AI自动创建或审批让步、复检、改判、冲突裁决。
- 客户协议和国标同时适用时未按客户协议优先。
- 已发布标准源文件索引成功，但RAG无法返回对应源文件名和条款。

## 4. 测试数据策略

### 4.1 使用两套数据

| 数据 | 用途 |
| --- | --- |
| OpenSpec P0种子数据 | 快速验证已有演示链路，如 `Z001001`、`Z002001`、`Z003001`、`Z004001` |
| 本测试包PDF数据 | 从标准维护页面完整验证“上传PDF -> 发布索引 -> 检验判定 -> 引用解释” |

### 4.2 核心PDF数据

| 场景 | PDF |
| --- | --- |
| 合格/国标 | `GB-T-SIM-912-2026_Q235B_cold_rolled_sheet_national.pdf` |
| 不合格/可让步/客户协议 | `CUST-XNJC-SIM-2026-Q235B_customer_agreement.pdf` |
| 标准冲突 | 使用同一客户协议PDF建立V1和冲突V2两个同优先级结构化标准 |

标准冲突V2属于人工制造的冲突样本；其目的是验证结构化标准治理，不是新增真实协议PDF。

## 5. 测试执行阶段

### 阶段A：环境和菜单

- 登录成功。
- 左侧菜单完整。
- API文档可打开。
- 工作台无前端异常。

### 阶段B：标准维护和PDF索引

- 新增国标和客户协议。
- 上传PDF。
- 发布后源文件状态为成功，条款数大于0。
- RAG能检索对应PDF源文件名。

### 阶段C：核心业务判定

- 合格：`QUALIFIED`
- 不合格：`UNQUALIFIED`
- 可让步：`CAN_CONCESSION`
- 标准冲突：`STANDARD_CONFLICT`

### 阶段D：AI解释与风险

- 判定解释不改变规则结论。
- 可让步风险输出结构化字段。
- 低置信或缺信息时要求人工复核。
- AI建议可采纳/忽略，但不自动审批。

### 阶段E：证书与审计

- 合格可解释可出证原因。
- 不合格/可让步待审批/冲突均不能正式出证。
- AI评估记录可查询。

## 6. 风险和规避

| 风险 | 影响 | 规避 |
| --- | --- | --- |
| Embedding或ES不可用 | PDF源文件RAG无法命中 | 先记录降级，再用OpenSpec种子缓存验证AI解释 |
| 字典缺少扩展品种/牌号 | 20份PDF无法全量通过页面录入 | 执行可选SQL或只用核心Q235B场景 |
| 冲突V2影响后续客户场景 | 同客户检验持续进入冲突 | 最后执行冲突场景，执行后删除V2或完成裁决 |
| 模型输出置信度波动 | HIGH/MEDIUM不稳定 | 判定结论和引用完整性优先，置信度band作为观察项 |
| PDF解析表格文本顺序变化 | RAG段落略有差异 | 断言来源文件、条款主题和关键限值，不要求逐字一致 |

## 7. 缺陷分级

| 级别 | 标准 |
| --- | --- |
| P0阻断 | 核心结论错误、无证据编造、冲突未阻断、AI越权审批、正式出证门控失效 |
| P1严重 | RAG引用缺失、PDF索引失败不可恢复、让步风险字段缺失、裁决后不重判 |
| P2一般 | UI文案不清、置信度标签不稳定、来源排序不理想 |
| P3建议 | 表格列宽、提示优化、操作便利性 |
